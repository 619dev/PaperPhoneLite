PaperPhoneLite — лёгкий мессенджер со сквозным шифрованием без публичных социальных функций.

## Возможности

- X25519 · XSalsa20-Poly1305 · Ed25519.
- Личные чаты и группы до 2 000 участников с шифрованием Sender Key.
- Текст, изображения, видео, документы, голосовые сообщения, эмодзи и стикеры Telegram.
- Надёжная WebSocket-синхронизация, офлайн-очередь и раздельный кэш аккаунтов.
- Автоудаление сообщений через 1, 3, 7 или 30 дней.
- Заявки в друзья, заметки, теги, блокировка и QR-приглашения в группы.
- TOTP 2FA, дополнительные уведомления ntfy на Android и пользовательские адреса Bark на iOS. По умолчанию сервер разрешает только `api.day.app`; собственные хосты Bark добавляются через `BARK_ALLOWED_HOSTS`.
- Файлы до 500 МБ хранятся в постоянном томе сервера; аватары пользователей/друзей и групп сохраняются постоянно, вложения чатов удаляются по настроенному на сервере сроку, а старые загрузки переносятся автоматически.
- Восемь языков интерфейса.

## Проверка личности, подписи и офлайн-синхронизация

Эти изменения протокола **ещё не выпущены**; версия остаётся 3.1.0. См. [журнал изменений](changelog.md).

Согласуйте пароль оформления текста офлайн, задайте его на устройстве и разблокируйте. **Этот пароль служит подтверждением доверия к собеседнику. Передавайте его только офлайн и никогда не отправляйте в Интернет ни в каком виде.** Проверка шифрует ровно `paperphone.app` с помощью AES-GCM, связывает личности, прежний номер безопасности из 12 групп и случайные запросы, затем подписывает зашифрованный конверт Ed25519. Зелёный ✅ в профиле появляется после взаимной проверки доказательств и подтверждений получения запросов. Сверяйте номера безопасности по доверенному офлайн-каналу.

Открытие профиля обновляет ключи, проверяет локальные записи доверия и восстанавливает подтверждения из истории. Разблокированный пароль позволяет автоматически начать или продолжить проверку. Повторное открытие сохраняет текущий запрос и ограничивает повторы. Смена ключа отменяет доверие и требует ручной проверки после офлайн-сверки. Возврат фокуса или видимости страницы также обновляет состояние.

Все новые групповые сообщения требуют подписи и шифрования Sender Key. Старые группы мигрируют, отключить шифрование нельзя. Перед раздачей ключей каждый участник должен пройти личную проверку. Список участников обновляет ключи и доверие, но не запускает массовые личные проверки. Подпись защищает группу, отправителя, поколение ключа, ID, тип, ключи личности, имя, nonce и шифротекст. Верная подпись доверенного ключа даёт зелёный ✅; без ключа расшифрования содержимое остаётся заблокированным.

Вступление, выход и исключение увеличивают поколение ключей. Участники онлайн немедленно меняют собственные ключи отправки после уведомления, остальные — при подключении и перед отправкой. Сервер отклоняет старое поколение. Ушедший участник не может отправлять или получать новые сообщения и ключи; повторное вступление не открывает период отсутствия. Оставшиеся получатели сохраняют исторические ключи. Уже полученные ключи и открытые тексты нельзя удалить с чужого устройства дистанционно.

Синхронизация сохраняет `server_seq` отдельно для аккаунта, загружает все страницы и повторяет расшифрование с историческими версиями ключей. История группы использует неизменяемые номера без фиксированного общего лимита. Локальный кэш ограничен 2 000 сообщениями на беседу, сроки автоудаления сохраняются. Потерянные ранее ключи восстановить нельзя.

Используются X25519, XSalsa20-Poly1305 и Ed25519. Старое поле API `kem_pub` содержит ключ подписи, а не рабочую постквантовую регистрацию ML-KEM. Состав группы и порядок определяет сервер, это не консенсус MLS. Метаданные и сами загруженные файлы вложений не получают сквозное шифрование благодаря подписям сообщений.

Обновляйте сервер и клиенты всех платформ согласованно: старые клиенты не понимают новые конверты. Обновление исходников не означает публикации приложений или образов Docker. См. [миграцию](DEPLOY_EN.md) и [тесты](client/tests/README.md).

## Tor обязателен

Рабочие клиенты Android, iOS, Windows и macOS должны встраивать Tor, ждать завершения bootstrap до входа и направлять `.onion` через изолированные SOCKS5-цепочки без перехода в clearnet. `client/` содержит только общий исходный код интерфейса. Браузеры и PWA не поддерживаются как рабочие клиенты.

Moments, Timeline, все звонки, LiveKit, Cloudflare R2, жалобы и панель модерации удалены. В рабочей среде используются только Docker Compose и Tor v3 onion service. См. [DEPLOY_EN.md](DEPLOY_EN.md).

При запуске сервер автоматически удаляет устаревшие таблицы Web Push и OneSignal вместе со старыми идентификаторами из прежних установок.

После запуска Docker Compose контейнер Tor автоматически записывает полный адрес `http://...onion` в файл `logs/onion-address.log` на хосте; адрес также выводится командой `docker compose logs tor`.

Приложение iOS предназначено для публикации в Apple App Store. APK для Android распространяются только через [GitHub Releases](https://github.com/619dev/ppl-android/releases) репозитория Android-клиента, не публикуются в Google Play и не содержат push- или сервисных фреймворков Google.
